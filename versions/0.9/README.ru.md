# Ktav 0.9 — черновой corpus диагностики

Этот каталог готовит версию 0.9.0; это не опубликованный релиз. Язык и существующие категории фикстур наследуют версию 0.8. Новые диагностические фикстуры находятся только в новой версии. Версия 0.8 не меняется.

## Координаты исходного текста

Ошибка разбора исходника несёт 1-based номер строки и полуинтервальный байтовый span в исходных данных. BOM и терминаторы LF, одиночный CR и CRLF не удаляются и не нормализуются перед вычислением смещений. CRLF считается одним терминатором. Позиция внутри терминатора принадлежит завершаемой им строке.

Для `UnclosedCompound` диагностика привязана к самому внутреннему незакрытому opener: строка соответствует opener, span идёт от opener до EOF. Для multiline-значений opener начинается с `(`, не с ключа пары.

Для `InvalidUtf8` проверка кодировки предшествует разбору грамматики. Span начинается с первой ошибочной последовательности, покрывает хотя бы один исходный байт и не выходит за входные данные. Реализации могут покрывать разную ширину ошибочной последовательности. Raw-byte фикстуры запрещено декодировать с заменой ошибочных байтов. Ошибкам I/O и отказам writer не приписываются выдуманные координаты исходника.

## Схема фикстур

Сохраняется пара `invalid/<name>.ktav` / `<name>.json`. Oracle может дополнительно содержать `expected_location` ровно одной из форм:

```json
{"line": 2, "start": 12, "end": 27}
```

```json
{"line": 3, "start": 33, "minimum_end": 34}
```

`line` положителен; остальные значения — неотрицательные байтовые смещения. `end` задаёт точную конечную позицию; `minimum_end` требует покрытия как минимум до этой позиции, но не за концом исходника. Эти два поля взаимоисключающие. Runner обязан проверять каждую объявленную позицию, а не только категорию ошибки. Все фикстуры `invalid/diagnostics09/` требуют такого oracle.

Manifest учитывает каждую новую фикстуру и помечает malformed UTF-8 как `raw_bytes`. Rust owned parser, strict parser, thin event parser и formatter проверяют UTF-8-фикстуры; `from_file` проверяет ошибочные байтовые данные. Прямые accessor ошибок и публичное преобразование в envelope обязаны совпадать. Native C ABI source operations используют тот же контракт координат.

Человекочитаемое сообщение не служит межъязыковым oracle координат. Существующая схема error-envelope из десяти полей не меняется; миграция делает координаты исходника полными и согласованными с прямым Rust API.
