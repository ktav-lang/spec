- **`versions/0.6/` не трогается никогда** — все фиксы (включая
  подтверждённые реальные баги уже выпущенной 0.6.4) применяются
  ТОЛЬКО в `versions/0.7/`, по двум явным подтверждениям пользователя
  в этой сессии.
- **§5.1 carve-out вместо переномерации правил**: первая попытка
  физически переставить местами правило-2 (comment) и правило-3
  (multiline) была откачена — существующий у blank-line правила
  паттерн "no effect except where stated (§5.6, multiline)" уже
  корректно решает точно такой же класс коллизии, без риска сломать
  внешние ссылки на номера правил (нашлась минимум одна — §5.0.1's
  "rule 2" — которую пришлось бы чинить при переномерации).
- **`::` (raw-маркер) обходит ВЕСЬ `<value-start>`-диспетчинг, не
  только §5.2**: проверено эмпирически через существующую фикстуру
  `inline/escape/braces` (`wrapped:: {value}` → `"{value}"`, не
  inline-object) — это же поведение распространено на `(`/`((`
  (multi-line opener collision) при построении §5.9.5's условия (f).
- **Третий независимый раунд ревью (`@oxx`, effort=max) оказался
  строже двух предыдущих** (rush-агенты): построение реального
  референсного парсера+writer выявило структурные round-trip дыры
  (leading/trailing whitespace fallback, key/item structural-token
  коллизии), которые чисто текстовый/грамматический анализ rush
  пропустил дважды подряд.
- **Локальный, ещё не запушенный коммит можно безопасно `--amend`**
  для исправления собственной опечатки/порчи в commit message —
  не нарушает правило "не амендить" (которое про уже опубликованную/
  переданную дальше историю).
